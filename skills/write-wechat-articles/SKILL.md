# 全领域公众号写作与排版

把模糊想法变成有读者、有证据、有立场的公众号文章，并在需要时输出可直接粘贴进微信公众号编辑器的 HTML。技能遵循开放 Agent Skills 目录规范，不依赖特定模型或另一个排版技能。

## 运行条件

- 写作、研究和 Markdown 交付不依赖脚本。
- HTML 排版需要 Agent 能运行 Python 3.9+；脚本只使用标准库。
- Agent 无法运行脚本时，仍应交付锁定后的 Markdown，并给出用户可在本机执行的命令，不要声称 HTML 已经生成或通过校验。

## 按需读取

- 确定结构时读 [article-blueprints.md](references/article-blueprints.md)。
- 涉及时效事实、数据、争议或专业领域时读 [evidence-and-risk.md](references/evidence-and-risk.md)。
- 初稿完成后必须读 [natural-chinese.md](references/natural-chinese.md)。
- 准备 Markdown 或 HTML 时必须读 [wechat-markdown-handoff.md](references/wechat-markdown-handoff.md)。
- 需要 HTML 时再读 [theme-index.md](references/theme-index.md) 和 [html-output.md](references/html-output.md)。

## 工作流

### 1. 识别任务

提取账号定位、稳定读者、主题、读者场景、主领域、文章类型、时效性、风险等级、已有材料、字数、口吻、争议强度、禁区和交付物。输入足以推进时直接工作；只有缺失信息会实质改变读者、结论或风险边界时，才问一个关键问题。

一个技能可以覆盖所有领域，一个账号不能毫无边界。若选题偏离账号定位，指出风险，并给出连接原目标读者的改写角度。

### 2. 选择交付模式

- 无主题：给 12 个候选选题，写清读者场景、核心冲突、可验证判断、证据需求和主要风险；按账号匹配、资料充足、实用、传播和争议评分，推荐 3 个。
- 用户要求先确认：交付选题或大纲后停止。
- 给定主题且要全文：直接研究、写作、编辑。
- 给旧稿：保留真实信息和原意，重构薄弱部分；不得同义替换式洗稿。
- 要系列：围绕同一读者和内容承诺设计 7、14 或 30 篇，说明承接关系。

### 3. 建立任务卡

在内部明确：写给谁、只解决什么问题、读者应记住什么、核心冲突、最强反方、证据需求和不可越过的边界。用户只要成稿时，不把内部工作过程塞进正文。

### 4. 研究和核查

涉及最新、陌生、可变、专业或高风险信息时必须检索。用户禁止联网时，只使用其材料与可确定事实，并列出待核实项。

优先一手材料和权威来源，核对人名、机构、日期、数字、引语、版本、口径与因果。区分已确认事实、来源观点、用户真实经历和本文推断。无法核实的内容要删除、降级或标注不确定；结论强度不得超过证据强度。

### 5. 设计有效争议

选择一个主冲突，最多加一个辅助冲突。争议来自事实、利益、价值、经验或判断差异，不靠虚构、误导或群体攻击。

- 批评观点、作品、产品、制度和公共行为，不羞辱普通人的身份或生活选择。
- 不用个案冒充规律，不虚构亲历、采访、内幕、数据、引语或“大家都认为”。
- 公平呈现最强反方，再回应或收窄结论。
- 全文写稳后再定标题；标题必须兑现正文，不使用无证据数字、恐吓或隐瞒关键条件。

### 6. 写正文

按 [article-blueprints.md](references/article-blueprints.md) 选择一个主结构，最多融合一个辅助结构。默认 1800—2800 字，讲透即可。

- 开头 150 字内出现对象与主要冲突，从场景、事实、细节或判断切入。
- 中段用 3—6 个表达判断的小标题，每节推进一个分论点。
- 重要判断后接数据、案例、原文、实测、机制或细节，并解释证据意味着什么。
- 至少写一处反方、限制或适用边界。
- 结尾回扣问题，只留一个具体互动问题或行动。

不得虚构第一人称经历。用户未提供个人经验时，使用可核验的观察角度。

### 7. 自然化编辑

按 [natural-chinese.md](references/natural-chinese.md) 做两遍：先删套话、模糊归因、宣传腔、机械连接词和无意义升华；再调整长短句、段落收束和作者声音，用具体细节替代抽象判断。不得为了“人味”虚构情绪、立场或经历。

### 8. 锁定 Markdown

按 [wechat-markdown-handoff.md](references/wechat-markdown-handoff.md) 整理标题层级、段落、强调、图片、代码块、署名和 CTA。排版阶段不得再改变事实、论点和实质内容。

### 9. 生成微信 HTML

当用户要求“HTML”“公众号排版”“自动排版”“一键粘贴”或“直接发布成品”时，必须完成此步：

1. 按 [theme-index.md](references/theme-index.md) 选主题；未指定时使用 `auto`。
2. 运行：

```bash
python scripts/render_wechat.py article.md --theme auto --preview
```

3. 脚本会生成纯正文 `*_wechat.html` 和带“一键复制”按钮的 `*_preview.html`，并自动调用平台校验。
4. 若 Agent 自己组装或修改了 HTML，额外运行：

```bash
python scripts/validate_gzh_html.py output_wechat.html
```

5. 校验失败必须修复后重跑。不得交付含 `<script>`、`<style>`、`<div>`、`class`、`id`、外链 CSS、定位布局或 CSS 变量的正文片段。

详细命令、输出边界和复制方法见 [html-output.md](references/html-output.md)。

## 输出约定

按用户要求裁剪，不机械展示幕后材料。

- 选题模式：候选表、推荐 3 题和选择理由。
- 大纲模式：任务卡、标题方向、核心观点、证据清单、详细结构和待核实项。
- 全文模式默认：主标题与 2 个备用标题、80—120 字摘要、完整正文、封面概念与配图建议、来源与事实核查表、必要风险、3 个后续选题。
- HTML 模式：除上述用户要求的内容外，必须给出纯正文 HTML 文件、预览复制页、主题名和校验结果。
- 用户说“只要正文”时，只交付标题、摘要和正文；关键数据仍保留可识别来源归因。

## 发布前验收

- 服务既定读者，只解决一个主要问题；标题、开头、正文和结尾兑现同一承诺。
- 核心观点可用一句话复述，关键判断有具体证据，事实、观点和推断已分开。
- 最强反方和边界得到公平处理；无虚构、洗稿、侵权、隐瞒利益关系或群体攻击。
- 医疗、法律、金融、新闻等内容符合更严格证据标准。
- 没有明显 AI 腔，段落适合手机阅读，文末只有一个主要动作。
- 若交付 HTML：正文片段已通过 `validate_gzh_html.py`；复制按钮只存在于预览外壳，不存在于正文片段。
