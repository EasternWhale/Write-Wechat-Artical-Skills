# 公众号 Markdown 与排版交接

## Markdown 正文规范

- `#` 只用于文章标题；
- `##` 用于 3—6 个主章节，标题表达判断；
- `###` 仅在教程或长文确有第二层结构时使用；
- 每段 2—5 句，连续长段主动拆分；
- 列表用于并列步骤、条件或选项，不把所有正文列表化；
- 表格只用于多字段比较，手机端列数宜少；
- 引用块只放真实引语、引言或必须突出的整段判断；
- 代码、命令和 Prompt 使用围栏代码块，行内标识用反引号；
- 正文使用中文全角标点，网址、代码和英文标识符除外。

## 视觉语义标记

- 最强锚点不超过 5 处，使用 `**加粗**`；
- 需要后续主题下划线的核心短语可使用 `++短语++`；
- 少量高亮可使用 `==短语==`；
- 不整段加粗或划线；
- 不用表情符号装饰章节；
- 图片使用 `![准确说明](URL)`；没有真实链接时写 `【配图建议：画面内容｜作用｜版权提醒】`；
- 空的图片说明不要硬编。

## 内容顺序

推荐正文交接顺序：

1. `# 主标题`
2. 可选的开头引用或摘要
3. 正文各 `##` 章节
4. 结尾互动问题
5. 可选作者签名区

作者未提供姓名与简介时，不擅自写死署名。若需要占位，只在末尾保留一次：

```markdown
我是 {{作者名}}，{{一句话简介}}。
```

不要重复生成“点赞、在看、转发”段落。文末只保留用户指定的一个主要动作。

## 与 gzh-design 的边界

本技能负责：

- 文章选题、研究、结构、写作与自然化；
- 产出结构清楚、视觉语义明确的 Markdown；
- 提供图片位置、说明和版权提醒。

`gzh-design` 负责：

- 根据文章类型推荐或选择主题；
- 将 Markdown 映射到主题组件；
- 自动编号、目录、关键词标记、图片和签名组件；
- 生成可复制到微信公众号编辑器的 HTML 与预览页；
- 运行 HTML 平台合规校验。

用户明确要 HTML 或自动排版时，先锁定 Markdown 内容，再调用 `gzh-design`。不要在排版阶段重写事实和论点，也不要绕过其主题库凭记忆拼 HTML。

## 交接前检查

- 标题层级连续，没有多个 `#`；
- 每个 `##` 对应一个清楚分论点；
- 图片占位位于相关段落之后；
- 加粗、高亮和下划线没有滥用；
- 代码与 Prompt 没有混入普通段落；
- 没有半成品备注、聊天用语或事实核查说明混入正文；
- 作者签名和 CTA 只有末尾一处；
- Markdown 正文与事实核查表分开。
